# 未结束事件的反馈联动 — 设计文档

- 日期：2026-06-01
- 状态：已确认，进入实现

## 背景

项目进展记录中，"待讨论/待确认/待执行"是**未结束事件**。需要在时间线上以空心闪烁圆点突出，并支持对其添加"反馈"事件；有反馈后停止闪烁并用虚线连向反馈点。

## 已确认决策

1. 关联方式：**事件 id + reply_to**（反馈事件 `reply_to` = 原事件 `id`）。
2. 结束判定：**有反馈即结束**（原事件 id 被某条目 reply_to 引用即视为已结束）。
3. 反馈状况：**继承原事件状况**（颜色一致），用户只填反馈内容。
4. 连线：**竖直虚线段、两端圆弧连接**（round linecap），画线区适当加宽。
5. 反馈事件按**自己的 time** 在时间线排序。
6. 一对一：**一个未结束事件只关联一条反馈**。

## ① 数据模型

`ProgressEntry` 增加两个可选字段（向后兼容）：
- `id?: string` — 条目唯一标识（前端生成：`Date.now()` + 随机后缀）
- `reply_to?: string` — 反馈事件指向的原事件 id

未结束状态常量：`PENDING_STATUSES = ['待讨论','待确认','待执行']`。

派生（前端计算，不另存）：
- `repliedIds` = 所有条目中出现过的 `reply_to` 集合
- 未结束事件 e 若 `e.id ∈ repliedIds` → 已结束（不闪烁、画连线）
- 一对一：同一 id 若被多条反馈引用，取 time 最新的一条作为其反馈

后端 `backend/schemas/project.py` 的 `ProgressEntry` 同步加 `id`、`reply_to` 可选字段。

## ② 时间线视觉

| 事件类型 | 圆点 |
|---|---|
| 普通事件 | 实心圆（不变） |
| 未结束 & 未反馈 | 空心圆（描边=状态色、内透明）+ 闪烁动画 |
| 未结束 & 已反馈 | 空心圆、停止闪烁 |
| 反馈事件 | 实心圆，颜色 = 其 reply_to 原事件的状态色 |

**虚线连线**：已反馈的未结束事件节点 → 其反馈事件节点，之间叠加竖直虚线段（`stroke-dasharray`，`stroke-linecap: round`，颜色取状态色）。时间线左侧画线区加宽以容纳连线。

## ③ 编辑态交互

编辑表格中，每个未结束事件行的内容输入框后显示「反馈」按钮：
- 点击 → 紧随其后插入一条反馈草稿：`reply_to=该行id`、`status=继承`、`time=now`、内容待填
- 反馈行内容框前显示蓝色"反馈："标签
- 原事件已有反馈 → 不再显示「反馈」按钮
- 保存时给缺少 id 的条目补生成 id（保证关联键稳定）
- 删除反馈行 → 原事件 reply_to 引用消失，自动恢复闪烁、连线消失

## ④ 边界

- 老数据无 id/reply_to → 普通事件，行为不变
- 闪烁仅展示态时间线；编辑态表格不闪烁
- id 生成用运行时 `Date.now()` + 随机（前端运行时，非工作流脚本，可用）
